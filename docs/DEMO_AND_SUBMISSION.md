# Demo and Submission

## 75-second demo script

### 0–5 seconds

Show Sophie, birthday countdown and a selected-gift outcome preview.

Narration:

> “WishTrace helps busy people send thoughtful gifts on time.”

### 5–15 seconds

Open Sophie's profile. Show interests, one hint, dislike and budget.

> “Talia saves the person, date, budget and the little things Sophie mentions.”

### 15–30 seconds

Run discovery. Show real candidates and concise rejections.

> “WishTrace checks available gifts, removes anything late or over budget, and chooses from real products using Sophie's context.”

### 30–42 seconds

Show recommendation and evidence.

> “This is selected because it matches her gaming interest, stays within budget and can be completed through the validated merchant path.”

### 42–58 seconds

Show exact purchase review and Prava approval.

> “Talia sees the exact merchant and amount before Prava handles the authorized transaction.”

### 58–70 seconds

Return to receipt / gift secured, show personal note.

> “The result is verified, the gift is secured, and the personal message is ready.”

### 70–75 seconds

Closing:

> “Not another reminder. The intention is actually completed.”

## Required evidence

- working APK/build;
- repository/judge link;
- demo video;
- Prava IDs/status evidence;
- source boundary disclosure;
- OpenAI implementation explanation;
- pre-existing-work disclosure;
- what worked, failed and was learned.

## Backup demo

Record a full successful run before submission. Keep:

- local MP4;
- cloud-accessible MP4;
- screenshots;
- transaction evidence;
- the last complete real run recording plus correlation/transaction evidence.

The backup must be truthful. Do not splice a fake transaction into a live flow.

## Submission copy structure

1. One-line outcome.
2. User and problem.
3. Discover → decide → complete flow.
4. Why Prava is central.
5. Why OpenAI is material.
6. What was built during the hackathon.
7. Exact live/sandbox truth boundary and any unavailable step.
8. Demo/repo links.
9. Continuation plan.
10. Learning and limitations.

## Judge proof table

| Claim | Proof |
|---|---|
| real problem | short user feedback or clear workflow |
| complete action | end-to-end demo |
| model is useful | evidence-linked ranking |
| Prava is central | approval and authoritative result |
| safe spending | exact amount, merchant, idempotency |
| strong UX | five-second test and polished states |
| startup potential | repeat loop and business model |

## Final checklist

- Submit before internal target.
- Verify every link logged out/incognito.
- Verify video audio and resolution.
- Verify README commands.
- Verify no secrets.
- Verify source disclosure.
- Verify exact deadline and timezone.
- Keep screenshots of successful submission.
